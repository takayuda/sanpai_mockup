# 産廃DXシステム モック（第1期）

産業廃棄物 中間処理業者向け「産廃予約管理システム」の画面モックです。
エンジニアへの受け渡し（要件を詰めながら実装する）ことを目的としています。

対象は**第1期のみ**。配車ボード（車両割当編成）、売上・会計、マニフェスト／JWNET連携などは含みません。

## ファイル構成

| ファイル | 内容 |
| --- | --- |
| `emitter-portal.html` | **排出元（取引先）ポータル**。作成済みのワイヤーフレームをそのまま収録。仕様はこちらを優先。 |
| `processor-admin.html` | **処理業者（社内）管理画面**。単一HTML・Bootstrap 5。 |

ブラウザで直接開くだけで動きます（ビルド不要）。`processor-admin.html` は Bootstrap 5.3.3 と
Google Fonts を CDN から読み込むため、初回表示にはインターネット接続が必要です。

処理業者画面のヘッダーにある **「排出者側の画面」ボタン**（MOCKラベル付き）で排出元ポータルへ移動できます。
本番では不要なモック専用の導線です。戻るときはブラウザの戻る操作を使ってください。

## データ構成（ER図との対応）

添付のER図（`companies` / `plants` / `items` / `units` / `pickups` / `pickup_items`）に準拠し、
業務上必要な項目だけを追加しています。画面上のラベルは日本語に読み替えています。

| テーブル | 画面での呼び名 | 主な項目（画面ラベル） |
| --- | --- | --- |
| companies | 取引先 | 取引先名／フリガナ／排出事業者・運搬業者の区分／担当者／メールアドレス（ログインID）／電話番号／郵便番号・都道府県・住所／インボイス登録番号／振込先口座／与信区分／関連契約書／登録状態（招待中・本登録済） |
| plants | 拠点 | 拠点名／持込受入の可否／引取対応の可否／引取対応時間（開始・終了）／住所・電話番号 ＋ 受入時間枠（複数）・定休日・臨時休業日 |
| items | 品目 | 品目名／廃棄物区分（産業廃棄物・特別管理産業廃棄物・一般廃棄物）／有価物 |
| units | 単位 | 単位（kg・t・m3・個・台・袋） |
| pickups | 予約・実績 | 受付番号／取引先／拠点／区分（持込・引取）／日付／開始・終了時刻／ステータス／伝票番号／総重量／空車重量／正味重量／差異／差異理由／承認日時／取消日時・取消理由 ＋ 車両ナンバー・ドライバー |
| pickup_items | 予約明細 | 品目／単位／申告数量／実数量 |

補足:
- ER図の `receipt_number` は「当日の計量伝票番号」として入場受付時に採番します。
  取引先に案内する受付番号（`R-2026-0158` 形式）は排出元ポータルに合わせ**申請時**に採番します。
- `password` / `remember_token` は取引先が本登録時に設定するため、管理画面には表示しません。
- 重量はすべて kg（整数）で保持し、1,000kg 以上は t を併記表示します。

| 実績一覧 | `#actuals` | 実績の検索・差異確認・CSV出力 |
| 取引先マスタ | `#m_companies` | 取引先の作成と登録用URLの発行、編集 |
| 拠点マスタ | `#m_plants` | 拠点の基本情報 |

各画面の上部にある「**この画面の仕様メモ**」に、その画面の仕様・第1期スコープ外・**要確認事項**を
記載しています。要件を詰める打ち合わせはこのメモを起点にしてください。

ヘッダーの拠点セレクトで、承認キュー・ボード・入場受付・実績一覧の対象拠点を絞り込めます。
権限（ロール）による画面の出し分けは行いません。

## 取引先の新規登録フロー

```
① 社内で取引先を作成（社名・区分・関連契約書などを入力）
② 取引先ごとに固有の登録用URLが発行される
③ URLを取引先担当者へ送付（画面上でコピー／メール送付のモック操作が可能）
④ 取引先担当者がURLから本登録（メールアドレス・パスワード・住所等を入力）
⑤ 以降、そのアドレスでログインすると当該処理業者への予約が作成できる
```

取引先が処理業者を検索・選択する画面は設けません。招待された処理業者だけが取引先側に表示されるため、
取引先が本システムの導入企業を一覧できることはなく、選択で迷うこともありません。

モックでは取引先マスタの「新規取引先を作成」→「取引先の登録画面を開く」で ④ まで通して確認できます。

## 動かして確認できる業務の流れ

データはすべてブラウザ内のダミーです。**リロードすると初期状態に戻ります**。
日付は開いた日を基準に相対生成されるため、いつ開いても「本日」が成立します。

1. **承認キュー** で `R-2026-0158`（持込）を選択 → 事前チェックを確認 → 「承認する」（受入時間枠を調整可）。
2. `R-2026-0152`（引取）を承認 → **訪問日時の確定入力が必須**。集荷手配メモも記録できる。
3. `R-2026-0172`（川口ヤードへの引取依頼＝対応外）を選ぶと事前チェックが「要確認」になる → 「変更依頼」で理由必須・代替候補の提示を確認。
4. **予約一覧ボード**（本日）で、持込の「枠変更」、引取の「訪問日時変更」を実行。
5. **入場受付・計量** で「入場受付」（伝票番号を採番）→「計量入力」
   → 総重量 − 空車重量から正味重量が自動算出され、申告との差異が大きい場合は理由入力を要求。
6. **実績一覧** で差異を確認し、CSV出力。
7. **受付時間・休業日** で受入時間枠の追加／削除、引取対応時間の変更、臨時休業日の登録。
8. **取引先マスタ** で新規取引先を作成 → 登録用URLを発行 → 登録画面を開いて本登録まで確認。
9. **監査ログ** に、ここまでの操作が記録されていることを確認。

## 仕様書との差分・要確認事項

| # | 論点 | モックでの扱い | 確認したいこと |
| --- | --- | --- | --- |
| 1 | 受付番号の採番タイミング | **申請時**に採番（排出元ポータルに合わせた） | 仕様書は「承認時に採番」。どちらに寄せるか |
| 2 | 引取の希望時間 | 開始・終了の希望時刻を受け付け、承認時に確定時刻を返答 | 「午前／午後」の選択にする案もある。どちらが運用しやすいか |
| 3 | 受入時間枠の粒度 | 拠点ごとに複数設定（既定は午前・午後の2枠） | 1時間刻みの要望があるか。拠点ごとでよいか |
| 4 | 上限管理 | **受付上限は設けない**（枠ごと・品目別・引取件数とも） | 将来的に上限が必要になる場面があるか |
| 5 | 1台に複数品目 | 品目ごとに実数量を手入力（正味重量との差はアラート表示のみ） | 実数の按分ルールを決める必要あり |
| 6 | 新着通知 | 画面内の通知のみ | LINE／LINE WORKS／メールのいずれか。**運用可否を左右するため優先確定** |
| 7 | 登録用URL | 有効期限なし・再発行は画面から何度でも可能 | 有効期限と再発行の運用ルール |
| 8 | 複数処理業者からの招待 | 未実装（1社からの招待のみ） | 取引先が複数の処理業者を持つ場合のログイン後の選択画面 |
| 9 | 拠点 | 2拠点を用意し、ヘッダーで切替 | 第1期は単一拠点想定でよいか |
| 10 | 認証・ログイン | 未実装 | 認証方式（仕様書でも「別途決定」） |

画面ごとの細かい確認事項は、各画面の「この画面の仕様メモ」に記載しています。

## 第1期に含まないもの（モックにもありません）

- 売上・会計（売上明細の生成、請求書発行、CSV連携、月次締め）
- 配車ボード＝車両・ドライバーの割当編成、運行指示書出力、地図表示、ルート最適化
- 受付上限の設定（着車数・処理量・品目別・引取件数）
- 権限（ロール）による画面の出し分け
- マニフェスト管理・JWNET連携
- 契約・単価マスタ、コンテナの在庫・配置管理、構内工程管理

引取については、第1期のシステムの役割は「集荷依頼を受け、承認し、訪問日時を返し、集荷実数を記録する」までです。
集荷手配そのものは台帳・電話などの既存手段で行い、モックでは「集荷手配メモ」欄に記録するだけにしています。

## 技術メモ（実装担当者向け）

- `processor-admin.html` は単一ファイル。Bootstrap 5.3.3（CDN）＋素の JavaScript。ビルドツールなし。
- 配色・角丸・タイポグラフィは排出元ポータルのトークンをそのまま Bootstrap の CSS 変数に上書きして揃えています。
- アイコンはインラインSVG（線画）を `ICONS` に定義し、`ic('名前')` で描画しています。
- 構造は「状態（`state`）→ `render()` で画面全体を描き直す」という単純な形です。
  Vue / React などに置き換える前提で読んでください。
- ダミーデータは先頭の `PLANTS` 〜 `PICKUPS` 付近に集約。過去45日ぶんの実績は固定シードの
  疑似乱数で生成しているため、開くたびに同じ内容になります。
- 主要なロジックは関数に分離してあり、サーバ実装の仕様として読めます。
  - `isClosed()` / `countOf()` / `slotOf()` … 稼働日・時間枠の判定
  - `checksOf()` … 承認時の事前チェック
  - `declaredKg()` … 申告数量の重量換算（kg・t のみ換算）
- 状態はメモリ上のみでの保持です。永続化・API・認証は未実装です。
