# 産廃DXシステム モック（第1期）

産業廃棄物 中間処理業者向け「産廃予約管理システム」の画面モックです。
エンジニアへの受け渡し（要件を詰めながら実装する）ことを目的としています。

対象スコープは**第1期のみ**（仕様書「20260727_産廃システム仕様書_v2」2.1 参照）。
配車ボード（車両割当編成）・請求書発行・JWNET連携などの第2期以降の機能は含みません。

## ファイル構成

| ファイル | 内容 |
| --- | --- |
| `emitter-portal.html` | **排出元（取引先）ポータル**。作成済みのワイヤーフレームをそのまま収録。仕様はこちらを優先します。 |
| `processor-admin.html` | **処理業者（社内）管理画面**。今回追加したモック。単一HTML・Bootstrap 5。 |

どちらもブラウザで直接開くだけで動きます（ビルド不要）。
`processor-admin.html` は Bootstrap 5.3.3 と Google Fonts を CDN から読み込むため、
**初回表示にはインターネット接続が必要**です。

## ロールと権限

画面右上のセレクトでロールを切り替えると、サイドバーの利用可否が変わります
（利用できない画面は「権限外」表示）。

| ロール | 利用できる画面 |
| --- | --- |
| システム管理者 | すべて |
| 受入責任者 | 承認キュー／ボード／受入枠／入場受付・計量／実績／品目・車格・容器マスタ／監査ログ |
| 配車責任者 | 承認キュー／ボード／引取枠／実績／現場マスタ／監査ログ |
| 営業 | 承認キュー／ボード／代行入力／実績／取引先・現場・取引関係・契約・単価マスタ |
| 計量・構内担当 | ボード／入場受付・計量／実績／品目・車格・容器マスタ |
| 経理 | 実績／締め処理・売上／取引先・契約・単価マスタ／監査ログ |

この割当はモック上の仮置きです。実際の運用に合わせて要調整（受入責任者と配車責任者は兼務あり）。

## 動かして確認できる業務の流れ

データはすべてブラウザ内のダミーです。**リロードすると初期状態に戻ります**。
日付は開いた日を基準に相対生成されるため、いつ開いても「本日」が成立します。

推奨デモ手順（第1期の「予約 → 受入判断 → 計量実数 → 売上」が一本につながることを確認できます）:

1. **承認キュー** で `R-2026-0158`（持込）を選択 → 事前チェックと枠の消化状況を確認 → 「承認する」
   → 承認キューから消え、受付番号が予約一覧ボードに載る。
2. 同じく `R-2026-0152`（引取）を承認 → **訪問日時の入力が必須**（C-05／A-09）。
3. `R-2026-0161`（契約未締結の取引先）を選び「変更依頼」→ 理由必須・代替候補の提示を確認。
4. **予約一覧ボード**（本日）で、持込の「時間帯変更」、引取の「訪問日時変更」を実行。
5. **入場受付・計量** で `R-2026-0165` を「入場受付」→「計量入力」
   → 総重量・空車重量から正味重量が自動算出され、申告との差異に理由入力を要求。
   → 「実績を確定して売上明細を作成」で契約単価が適用された売上明細が生成される。
6. **締め処理・売上一覧** で当月の売上・仕入（有価物）を確認 → 「締める」
   → 締め後は実績が編集不可になり、**赤伝**での修正に切り替わる（実績詳細から起票）。
7. **監査ログ** に、ここまでの操作がすべて記録されていることを確認。

そのほか確認できるもの:
- 受入枠設定：カレンダーのセルから当日を含む枠の緊急変更・臨時休業（B-08）、曜日パターンの一括適用（B-06）
- 引取枠設定：「稼働車両台数 × 1台あたり想定訪問件数」からの既定値算出（B-05）
- 代行入力：申請者・排出事業者を選ぶと右側で契約／許可／代理関係／枠が即時チェックされる（A-06）
- 実績一覧・売上一覧・マスタ・監査ログの CSV 出力（実際にダウンロードされます）
- 飛び込み搬入の直接登録（C-07）、受入拒否・集荷不可の記録（D-05）

## 仕様書との差分・要確認事項

排出元ポータル（作成済みモック）の仕様を優先しているため、仕様書と食い違う点があります。

| # | 論点 | モックでの扱い | 確認したいこと |
| --- | --- | --- | --- |
| 1 | 受付番号の採番タイミング | **申請時**に採番（排出元ポータルに合わせた） | 仕様書 A-08 は「承認時に採番」。どちらに寄せるか |
| 2 | 引取の時間指定 | 開始・終了の**希望時刻**を受け付け、承認時に訪問日時を確定 | 仕様書 A-03 は「時間帯の指定は行わない（または午前／午後の希望のみ）」 |
| 3 | m3 品目の枠消費 | 重量換算係数 0.3t/m3 の暫定値で総処理量に加算 | 品目マスタに換算係数を持たせるか。そもそも体積枠を別に持つか |
| 4 | 枠の消費量 | 承認済・申請中とも**申告数量**ベースで消費 | 計量後に実数へ置き換えるか |
| 5 | 1台に複数品目 | 品目ごとに実数量を手入力（正味重量との差はアラート表示のみ） | 実数の按分ルールを決める必要あり |
| 6 | 新着通知 | 画面内のトースト表示のみ | LINE／LINE WORKS／メールのいずれか。**運用可否を左右するため優先確定**（G-01） |
| 7 | 締め日 | 月末締め固定 | 取引先ごとの締め日（20日締め等）への対応要否 |
| 8 | 消費税 | 明細は税抜のみ | 税計算・端数処理・インボイス対応の要件 |
| 9 | 拠点 | 単一拠点前提（セレクトは表示のみ） | 複数拠点展開時のデータ構造の持ち方 |
| 10 | 認証・ログイン | 未実装 | 認証方式（仕様書でも「別途決定」） |

画面ごとの細かい確認事項は、各画面の「この画面の仕様メモ」に記載しています。

## 第1期に含まないもの（モックにもありません）

- 配車ボード＝車両・ドライバーの割当編成、運行指示書出力、地図表示、ルート最適化（第2期以降）
- 請求書発行・インボイス帳票（第2期）、会計ソフトAPI連携（第3期）
- マニフェスト管理・JWNET連携
- 出勤者数連動の動的な処理能力算出
- コンテナの在庫・配置管理
- 構内工程管理・在庫管理

引取については、第1期のシステムの役割は「集荷依頼を受け、承認し、訪問日時を返し、
集荷実数を記録する」までです。集荷手配そのものは台帳・電話などの既存手段で行い、
モックでは「集荷手配メモ」欄に記録するだけにしています。

## 技術メモ（実装担当者向け）

- `processor-admin.html` は単一ファイル。Bootstrap 5.3.3（CDN）＋素の JavaScript。
  ビルドツール・フレームワークは使っていません。
- 配色・角丸・タイポグラフィは排出元ポータルのトークンをそのまま Bootstrap の CSS 変数に
  上書きして揃えています（`:root` の `--blue-800` などを参照）。
- 構造は「状態（`state`）→ `render()` で画面全体を描き直す」という単純な形です。
  実装を Vue / React などに置き換える前提で読んでください。ファイル内のコメントは
  仕様書の機能ID（C-01 など）に対応しています。
- ダミーデータは先頭の `PARTNERS` 〜 `RESV` 付近に集約。過去45日ぶんの実績・売上は
  固定シードの疑似乱数で生成しているため、開くたびに同じ内容になります。
- 主要なロジックは以下に分離してあるので、サーバ実装の仕様書として読めます。
  - `capacityOf()` / `pickupLimitOf()` / `usageOf()` … 枠の算出と消化（B-02〜B-09）
  - `checksOf()` … 承認時の事前チェック（A-06 / C-08 / C-09）
  - `buildSalesFor()` … 実績から売上明細の生成（F-01〜F-04）
- 状態はメモリ上のみでの保持です。永続化・API・認証は未実装です。
